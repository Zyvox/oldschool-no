Design tokens

Three tiers. A raw palette of colour ramps; semantic colours and role tokens that components actually use; and themes that decide which shades and sizes feed them. Components never see a hex value.

Everything below is read from the live stylesheet — change theme, mode or density in the grey bar and the values update.

Semantic colours

What a colour is for. The badge shows contrast against --os-color-surface in the current theme and mode. npm run check verifies every text/background pair for every theme × mode.

Role tokens

Spacing, corners, type and control sizes by role. Themes and data-density re-point these — retro is the 2008 sizing; compact makes it one step tighter.

Type scale

Verdana 12px in the retro theme, Arial 14px in standard — fixed pixel steps, just like the pages it is modelled on. No web fonts, no fluid type. Values below follow the theme picked in the grey bar.

Palette

Every ramp grows from one seed in tokens/palette.mjs. The lightness of each step is fixed, so any seed keeps the contrast guarantees — change accent and rebuild to re-brand (try it on the themes page). accent and neutral are emitted in full as --os-accent-* and --os-neutral-*; the others only with the steps the semantic colours use.

Icons

Used sparingly — in action rows and buttons, always next to a word. Lucide (ISC), bundled into one sprite: <svg class="os-icon"><use href="icons.svg#os-name"></use></svg>.
